# PDF workflow

This folder contains two complementary ways to collect home-visit data:

- `homevisit_form_v1.html` — the primary offline form. It is best for Thai text, autosave, and direct Markdown/LaTeX export.
- `dist/homevisit_form_fillable.pdf` — a computer-fillable AcroForm PDF covering the full form. It can be opened in a desktop PDF viewer and saved with checkbox/text values.

## Rebuild the fillable PDF

From this folder:

```bash
NODE_PATH=/tmp/hvtest/node_modules node tools/pdf_export/render_form_manifest.js
python3 tools/pdf_export/build_fillable_pdf.py
```

The first command prints the HTML form to an A4 PDF and records every field position. The second command places AcroForm widgets over the printed form.

## Extract a completed PDF

```bash
python3 tools/pdf_export/extract_pdf_data.py \
  dist/completed_homevisit.pdf \
  -o dist/homevisit_data.json
```

The JSON contains:

- `fields` — exact PDF field names and values
- `by_data_key` — values mapped back to the HTML `data-k` paths

That JSON is the hand-off source for the future report/slide generators:

```text
completed PDF → homevisit_data.json → LaTeX report
                                      → Marp Markdown → slide PDF
```

## Important limitation

The PDF background renders Thai labels correctly. AcroForm widgets generated by the current ReportLab toolchain use standard PDF fonts, so Latin text, medication sigs, numbers, and checkboxes are safest in the PDF. For free-form Thai narrative, use the HTML form and its JSON/Markdown/LaTeX export; alternatively type Thai in a PDF viewer that substitutes a Thai-capable font.

Do not put completed patient PDFs or extracted JSON into GitHub unless the repository and access policy explicitly allow that. The generated patient-data JSON is ignored by `.gitignore`.
